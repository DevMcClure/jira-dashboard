# Sprint Atlas

A proof-of-concept Jira sprint dashboard. It reads a **JSON export of Jira data** (produced by the separate *Jira Trawler* script) and visualises ticket counts, remaining work, sprint progress, workload and how tickets move through the workflow over time.

Everything runs in the browser: no backend, no API calls, no auth, no secrets.

![Sprint Atlas overview](docs/screenshot-overview.png)

## Pages

| Page | What it shows |
|---|---|
| **Overview** | KPI cards (total, remaining points, completed, blocked) with weekly deltas and 14-day sparklines, sprint burndown, status donut, recent movements, sprint health, tickets by assignee |
| **Tickets** | Sortable, filterable data table (search, status/type/priority/assignee facets, column visibility, pagination). Click a row for a detail sheet with the ticket's full history |
| **Sprints** | One card per sprint: progress, status mix, scope change. Click to filter Tickets and set the burndown sprint |
| **Teams** | Remaining work, velocity (committed vs completed) and members per team |
| **People** | Workload per assignee, including Unassigned, sorted by open points |
| **Movements** | Cumulative flow diagram, created vs resolved, transitions per day, and a filterable log of every status change |
| **Import** | Drag-and-drop a new export, see validation errors, reset to sample data, download the current data |

The header filters (Sprints, Teams, Assignees) apply to every page.

## Run it

Requires **Node 20.19+** (Node 22 recommended — there's an `.nvmrc`).

```bash
nvm use            # optional, picks up .nvmrc
npm install
npm run dev        # http://localhost:5173
```

| Command | Does |
|---|---|
| `npm run dev` | Start the dev server |
| `npm run build` | Type-check and build to `dist/` |
| `npm run test` | Run the Vitest suite (metrics, adapter, mock-data consistency) |
| `npm run lint` | Lint with oxlint |
| `npm run mock:data` | Regenerate `src/data/jira-export.json` |

## Sample data

`src/data/jira-export.json` is generated by `scripts/generate-mock-data.ts`: 3 teams, 14 people, 12 sprints (two closed, one active, one future per team) and 180 tickets with internally consistent changelogs (weekday working hours, realistic back-and-forth between statuses, carry-overs between sprints).

The generator is seeded, so `npm run mock:data` always produces the same file. Its rules are checked by `src/data/jira-export.test.ts`.

**"Now" is the export's `meta.generatedAt`** (19 Oct 2026 for the sample), not the real clock. That keeps every "this week", "days left" and burndown reading the way it did when the snapshot was taken.

## Plugging in a real Trawler export

Two ways to use real data:

1. **At runtime** — open **Import** and drop the JSON file in. It's validated, then remembered in this browser's local storage until you hit *Reset to sample data*. Nothing leaves the browser.
2. **As the bundled default** — replace `src/data/jira-export.json`. Keep real company data out of git: the `.gitignore` already ignores `exports/`, `*.real.json` and `jira-export.*.json`.

The expected format is documented in [`docs/02-DATA_CONTRACT.md`](docs/02-DATA_CONTRACT.md) (and a short example is on the Import page).

### If the real output has a different shape

Only the adapter needs to change. The app is layered so nothing else knows the raw JSON shape:

```
raw JSON ──► schema.ts (zod) ──► adapter.ts ──► JiraDataset ──► metrics.ts / hooks ──► components
```

- **`src/lib/jira/schema.ts`** — zod schemas for the raw file. Strict on what the dashboard needs (`key`, `summary`, `status`, `statusCategory`, `created`, `changelog`), lenient on everything else, and extra fields pass through.
- **`src/lib/jira/adapter.ts`** — `parseExport(raw)` maps the raw file to the typed `JiraDataset` (dates → `Date`, sorted changelogs, lookup maps, flattened status transitions). Rename fields, convert Jira's native changelog format, derive `statusCategory`, etc. here.
- **`src/lib/jira/types.ts`** — the domain model the rest of the app relies on. Keep this stable.

Unknown statuses are fine: they're grouped and coloured by the issue's `statusCategory`. People referenced but not listed become "Unknown (id)". A file that fails validation shows a toast plus a readable list of problems, and the previous data stays loaded.

## Project layout

```
docs/                     planning docs (build plan, data contract, UI spec)
scripts/generate-mock-data.ts
src/
  pages/                  one file per route (lazy-loaded)
  components/
    layout/               sidebar, header, page header
    dashboard/            Overview cards and charts
    tickets/              TanStack table, toolbar, detail sheet, timeline
    sprints/ teams/ people/ movements/ import/
    common/ filters/ theme/
    ui/                   shadcn/ui (generated)
  context/                DataProvider (current dataset, upload, filters)
  hooks/                  useFilteredIssues, useData, …
  lib/jira/               schema, types, adapter, constants, metrics (+ tests)
  data/jira-export.json   sample export
```

## Stack

Vite · React 19 · TypeScript (strict) · Tailwind CSS v4 · shadcn/ui (new-york, neutral) · Recharts via shadcn charts · TanStack Table v9 · React Router · zod · date-fns · Vitest.

Dark mode is the default; the sun/moon button in the header toggles it (remembered per browser). `Ctrl/⌘ + B` toggles the sidebar.
